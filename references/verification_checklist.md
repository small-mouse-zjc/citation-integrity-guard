# 来源与论断核验清单

本清单服务于引用管理任务中"对得上"这一维度。逐句执行，结论写入 `claim_source_map` 与 `uncertainty`。

## A. 条目真实性（这条引用指向的文献真实存在吗）

- [ ] DOI 是否已归一化和记录？
- [ ] 能否通过 DOI 解析 / 数据库检索 / 原文比对确认条目存在？
- [ ] 若无法核验：标注 `doi_unverified`，**不要**据此断言条目不存在或编造替代条目。
- [ ] 题名、作者、年份、刊名、卷期页与权威来源是否一致？不一致处记录差异。

## B. 元数据准确性

- [ ] 作者姓名拼写与顺序（尤其姓/名、重音字符、中文拼音）是否正确？
- [ ] 年份、卷、期、页码、DOI 是否与来源一致？
- [ ] 文献类型标识（[J]/[M]/[D]/[C]...）是否与载体一致？
- [ ] 预印本与正式版是否混用？正文引用优先指向正式版，标注版本差异。
- [ ] 字段缺失是否如实留空并记录，而非猜测填充？

## C. 正文论断与所引文献匹配（逐句）

对正文每个带引用的论断句回答：
- [ ] 所引文献的主题是否覆盖该论断？
- [ ] 文献的结论是**支持**、**部分支持**、**无关**还是**相反**？
- [ ] 论断中的数字、范围、限定词是否来自所引文献？有无被正文加强/削弱？
- [ ] 一句多引时，每条文献是否各自支撑其中一部分？
- [ ] 多句一引时，该文献是否覆盖全部相关句子？
- [ ] 证据不足或主题不符：写 `claim_source_mismatch` / `partial`，给出主题差异说明，交作者确认，**不擅自改论断**。

`match` 取值：`supported`（支持）/ `partial`（部分支持）/ `mismatch`（不符）/ `unverified`（无法核验）。

## D. 引用位置与形式（挂得对）

- [ ] 引用是否插在真正需要来源支撑的那句话/那个位置，而非段末笼统堆砌？
- [ ] 顺序编码制 / 著者—出版年制 / 脚注 是否与目标规范一致？
- [ ] 一句多引、多句一引的形式是否规范？

## E. 编号与列表一致性（编得顺）

- [ ] 运行 `verify`：`dangling_citations` 为空（无悬空引用）。
- [ ] `uncited_entries` 为空（文末条目都被正文引用）。
- [ ] `duplicate_numbers` 与 `numbering_gaps` 为空（编号连续无重复）。
- [ ] 插入/删除/调序后，图表注、附录引用是否同步更新？

## F. 去重正确性（收得净）

- [ ] 每次合并是否由 `dedup_decisions` 的判据和证据支撑？
- [ ] 置信度低于阈值的疑似重复是否留在 `needs_review` 而非自动合并？
- [ ] 是否避免误合并同名作者的不同文献？

## G. 最终交付前

- [ ] `case_id` 与输入一致。
- [ ] `result.json` 含题目要求的全部 output_contract 字段。
- [ ] 可编辑稿件与文献表已另存，编号与 `number_mapping` 一致。
- [ ] 所有 `partial` / `needs_review` 项都有明确的 `uncertainty` 说明与人工接管位置。
- [ ] 没有编造任何文献、元数据、数字或 benchmark 分数。
