# 六类要素清单：定义、判据与常见遗漏

"写得全"要求方法与实验章节覆盖六类要素。`check-completeness` 用关键词规则做初检，Agent 须核对语义完整性。

## 六类要素

| 要素 | key | 必须回答的问题 | 常见遗漏 |
|------|-----|--------------|---------|
| 方法步骤 | steps | 每步的输入、操作、输出、判断条件是什么？ | 把多步操作压成一句；跳过去重/异常分支 |
| 实验设置 | setup | 训练/验证/测试如何分开？硬件、软件、版本、种子、重复次数？ | 条件串台（train 用了 test 数据）；漏种子 |
| 参数 | params | 每个超参的名称、取值、单位、作用对象、来源？ | 只报主干参数；数值无来源 |
| 数据集与划分 | data | 名称、版本、规模、预处理、划分比例与随机方式、各子集用途？ | 版本含混；划分无随机方式导致不可复现 |
| 对照实验 | baseline | 基线对象及版本、是否同预算、评价指标与统计方式？ | "与基线比较"却是断言；无统计显著性 |
| 可复现与限制 | repro_limit | 代码/环境/命令/数据获取是否给全？限制指向什么具体场景？ | 只有"存在局限"套话；无复现入口 |

## 判据说明

脚本用正则关键词判断"是否出现相关表述"，是**宽松初检**——出现关键词不代表写全，Agent 须进一步核对：
- 步骤是否真的有序、可执行（每步四要素齐）；
- 设置是否真的分开训练/验证/测试；
- 数据是否真的给了版本与划分方式。

## 可裁剪

通过 `required_elements` 可按场景调整必查项。例如纯方法论文可能弱化"对照实验"，强化"参数来源"。裁剪须在 uncertainty 说明。

## 写成可执行步骤

好的步骤："步骤2 特征提取：输入为预处理后的 512×512 薄片图像，采用 3×3 卷积核提取纹理特征（PyTorch 1.13 torch.nn.Conv2d），输出 256 维特征向量；若输入分辨率不足 256 则跳过并记入 logs。"
坏的步骤："然后做特征提取。"——无输入/操作/输出/判断条件，会被判不完整。
