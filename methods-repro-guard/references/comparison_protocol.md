# 公平对照协议（写作09 方法与实验章节写作）

服务于"使用增益 25 分"与"创新证据 5 分"：加载 Skill 后相对基础 Agent 是否有可验证改善。

## 对照设计
- **同一输入**：基线与 Skill 使用完全相同的 case 输入（事实底稿/受众/文体/格式约束）。
- **同一条件**：相同模型、相同请求上限、相同 token 预算、相同超时。
- **基线**：不加载 Skill，直接按指令产出；基线失败按题面四问的常见失败建模。
- **Skill**：先跑 `methods_engine.py` 确定性检查与门禁，再成稿并核对来源映射。

## 四问对照表
| 核心问题 | 基线常见失败 | Skill 检查机制 |
|---|---|---|
| 写得全 | 关键步骤/参数/数据集遗漏 | 必需要素清单逐项检出 |
| 写得准 | 参数数值凭空补出无来源 | 数值溯源核对 |
| 做得着 | 版本/种子/命令不全无法复做 | 复现要素清单 |
| 说得住 | 材料缺口不显式标注 | 开放问题与待确认标注 |

## 度量边界（务必遵守）
- 本 Skill **不提供**质量分、效率耗时、平台白板对照结果——这些由组织方生成（`human_review_only`）。
- `compare_engine.py` 只度量"Skill 四问检查机制是否配置且真实触发"的可复现证据，客观呈现观测值，不替代人工评审对质量、忠实度、创新价值的判断。
- `benchmark.json` 含干净案例（验证不误报）与缺陷案例（验证能检出）；标注为示例/smoke 的输出不得冒充正式案例结果。
- 效率增益的实际数值由平台记录，本 Skill 只说设计（结构化中间结果、按需读取），不宣称具体节省数字。

## 复现
```bash
python scripts/compare_engine.py examples/benchmark.json
```
