# 相关工作分组维度模板

"分得清"的关键是把相关工作放到**同一把尺子**上比较，而不是逐篇摘要拼接。本文件给出可按学科调整的比较维度模板。

## 默认五维

`group-matrix` 的默认维度：`问题设定 / 方法路线 / 数据与评价 / 适用条件 / 局限`。

- **问题设定**：该工作要解决的具体问题（不是宽泛领域）。
- **方法路线**：核心技术路线（深度学习/生成模型/知识规则/传统 ML/图像分析……）。
- **数据与评价**：数据规模、来源、划分方式、评价指标。
- **适用条件**：方法成立的岩性/场景/前提假设。
- **局限**：作者自述或可归纳的限制。

## 分组依据（key_field）

推荐默认按"方法路线"（`route`）分组——它最能体现技术演进与取舍。也可按：

- **问题设定**：当领域按任务切分清晰时（如识别/生成/预测）；
- **数据模态**：当方法差异主要由数据驱动时（如薄片图像/测井曲线/地球化学）。

引擎对缺失 `route` 的文献会用题名/摘要关键词做**初始建议**并打上 `group_auto_suggested` 标记，须人工确认，不可直接采信。

## 学科维度调整示例

通过 `input.json` 的 `dimensions` 字段覆盖默认维度：

- **地球科学/沉积学**：问题设定 / 数据模态 / 模型方法 / 地质场景 / 可信与落地
- **医学影像**：任务 / 模态(CT/MRI) / 网络结构 / 数据集 / 评价指标 / 临床局限
- **NLP**：任务 / 预训练范式 / 微调方式 / 基准数据集 / 指标
- **材料科学**：体系 / 计算方法 / 特征描述 / 验证手段 / 适用温压范围

##  qualitative 比较矩阵写法

引擎输出的 `groups[].comparison` 是"维度 → [(文献id, 该维度取值)]"的横向视图。撰写时：

1. 每个分组写一段，段首点明该路线的共同取舍；
2. 段内用比较维度串起各工作，例如"在评价方式上，[3] 用准确率而 [7] 用 F1，二者口径不可直接比较"；
3. 段末点出该路线的局限，为下一节"研究空白"铺垫。

避免"张三做了X，李四做了Y，王五做了Z"式的逐篇罗列——那是 `needs` 触发信号，应回到本模板重组。
