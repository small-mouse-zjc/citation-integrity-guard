# 四部件写作细则与反例

## 研究背景（立得住）

必做：
- 领域对象具体（岩相/储层/材料/任务），不是“某领域”。
- 问题机制具体（为什么会难：数据、尺度、标注、评价、物理约束）。
- 为什么现在做：新数据、新方法、新需求、旧方法的具体失败。
- 每个事实判断带 `[w#]`；作者判断用“本文认为/我们假设”，不伪装成文献结论。

反例：
- “近年来，深度学习在各领域受到广泛关注。”——无对象、无问题、无引用。
- “该问题具有重要意义。”——空转。
- “已有大量研究。”——不说明哪类研究、做到什么程度、留下什么。

## 相关工作（分得清）

必做：
- 选一个主维度分组：问题设定 / 方法路线 / 数据与评价 / 适用条件。
- 同组内按**同一维度**比较，不要一篇一段地摘要。
- 每篇写“结论 + 条件 + 局限”；组末给取舍。
- 覆盖关键工作、代表性工作、近 3 年进展。

反例：
- “Smith 提出了 A。Li 提出了 B。Wang 提出了 C。”——流水账。
- 只写优点，不写适用条件与局限。
- 分组维度混用（第一组按方法、第二组按年份）。

## 研究空白（说得实）

必做：
- 空白来自已引工作的共同限制/未覆盖场景/冲突结论。
- 至少 2 篇支撑，写出推理链：“A 在 X 有效但受制于 Y [w1]；B 改进了 Y 但未覆盖 Z [w2]；因此 Z 场景仍缺……”。
- 说明本文如何填补：设计/数据/实验对应。

反例：
- “目前尚无相关研究。”——没有引用支撑。
- “本文首次提出……”——无证据的“首次”。
- 空白与后文方法不对应。

## 贡献表述（对得上）

必做：
- 2–4 条，每条“做了什么 + 在哪验证 + 结果/边界”。
- 每条对应 `claims.json` 的 id 与 evidence_refs（图/表/§/数据）。
- 用材料中的真实数值；没有就写方法层贡献。

反例：
- “本文显著提升了性能。”——无指标、无对照。
- “填补了领域空白。”——空泛。
- 贡献写了三个，正文只有两个实验支撑。

## 引用与元数据

- 引用 token 统一 `[w#]`，与 works id 一一对应。
- 每条 works 至少有 title/authors/year/source；缺项列入 `missing_metadata`。
- 不把综述当原始研究引用；不把“in press”写成确定年份。
- 同一论断引用 2–3 篇即可，不堆砌。
